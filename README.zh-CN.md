# NTFS 只读恢复工具

[English](README.md) | **简体中文** | [日本語](README.ja.md) | [Español](README.es.md) | [Deutsch](README.de.md)

一个本地网页工具，用来从损坏的 NTFS 分区里把文件取出来 —— 就是那种 Windows 显示为 **RAW**、打不开、还一直提示你格式化的分区。

它直接读原始磁盘，扫描整张 MFT（主文件表），再从每条记录里保存的「父目录引用」把目录树重建出来。所以哪怕根目录本身被毁掉，它依然能工作，而且保留原始文件名和文件夹结构。

**全程只读，不对源盘做任何写操作。**

## 为什么别的工具不行它能行

常规恢复工具走「分区 → 根目录 → 子目录 → 文件」这条链。一旦 MFT 第 5 条记录（也就是根目录）损坏，链条第一环就断了。Windows 判定分区为 RAW，多数工具只能看到一个空盘；少数继续往下走的，会退化成按文件头签名雕刻，文件名全丢。

NTFS 的文件记录是**自包含**的。每一条 1024 字节的记录里，都写着文件名、父目录的记录号、数据所在的簇。所以本工具完全绕开根目录：

1. 读引导扇区，拿到 MFT 起始位置和簇大小
2. 解析 `$MFT` 自己的数据段 —— MFT 本身也是一个文件，可能被碎片化成上百段、分散在好几条记录里
3. 顺序扫描每一条 MFT 记录，取出「父目录引用 + 文件名」
4. 反向聚合，重建整棵树

## 功能

- **根目录被毁也能救** —— 这是分区变成 RAW 最常见的原因
- **保留文件名和目录结构** —— 不是签名雕刻那种只能捞出无名碎片的方式
- **任意文件类型** —— 照片、视频、文档、压缩包都能取，不按扩展名过滤
- **坏道不会卡死** —— 每个数据块独立线程读取并带超时，读不动的区域跳过并计数
- **本地网页界面** —— 磁盘列表、诊断、扫描进度、目录树、类型筛选、提取进度
- **扫描结果有缓存** —— 关掉再打开不用重新扫
- **不依赖框架** —— 标准库 HTTP 服务 + 原生 JavaScript，没有构建步骤
- **严格只读** —— 代码里没有任何以写方式打开源设备的路径

## 环境要求

- Windows（原始设备访问是 Windows 特有的）
- Python 3.8 或更高
- `dissect.ntfs` —— 可选，只在 `$MFT` 碎片化严重时用来解析数据段

## 快速开始

```bash
git clone https://github.com/createBean/DiskRepairTool.git
cd DiskRepairTool
pip install dissect.ntfs
```

然后双击 `启动.bat`。它会自己申请管理员权限、缺依赖时自动安装、并打开浏览器界面。

也可以手动启动：

```bash
python server.py
```

服务监听 `http://127.0.0.1:8765/`。

手上没有故障盘？打开 `http://127.0.0.1:8765/?demo=1` 可以用示例数据预览界面。

## 使用步骤

1. **选磁盘** —— 按型号和容量挑出故障盘
2. **选分区 → 诊断** —— 检查引导扇区和 MFT 前 16 条记录，判断根目录是否损坏
3. **扫描** —— 读取整张 MFT 并重建目录树；百万级记录通常几分钟
4. **浏览勾选** —— 逐层点进目录，勾选需要的文件；面板上还会列出「图片最多的文件夹」
5. **提取** —— 选目标文件夹开始复制，进度和字节数实时更新

## 能力边界

**适用**：NTFS 逻辑损坏 —— 根目录丢失、分区表损坏、文件系统结构损坏、断电或未安全弹出后变成 RAW。

**不适用**：

- **物理损坏** —— 有咔哒异响、摔过、进水的盘。不要通电，需要无尘室开盘
- **exFAT / FAT32** —— 磁盘结构完全不同，未实现
- **加密卷** —— BitLocker / VeraCrypt 需要先解锁
- **记录被覆盖** —— 如果文件记录已经指向被回收的簇，内容无法通过记录恢复；只能靠签名雕刻，而那会丢失文件名

## 常见问题

**分区没有盘符。** 以管理员身份运行时，工具打开的是 `\\.\PhysicalDriveN`，不需要盘符。没有提权时会退回到卷句柄，这时才需要盘符。

**杀毒软件报警。** 属于预期 —— 行为特征（遍历所有磁盘、大量读取）很像勒索软件。源码不长，可以自行审阅；它只会以读方式打开设备。

**打包出来的 exe 打不开。** Windows 的智能应用控制和 SmartScreen 会拦截未签名、无信誉的可执行文件。改用源码运行，或者给二进制签名。

**扫描完什么都没有。** 先看诊断结果：如果引导扇区不是 NTFS，或者 MFT 数据段解析不出来，说明这块盘可能是物理损坏，或者用的是别的文件系统。

## 安全说明

- 程序只从源盘读取，没有任何以写方式打开它的代码路径
- 需要管理员权限仅仅是为了打开原始设备句柄
- 唯一的写入是写到你指定的目标文件夹
